fix(onboarding): advisers were being persisted as "student"

Phase 5 made the role conditional in order to stop a student self-
appointing as rep, but the ternary only had two branches:

    p.isRep && repDecision.granted ? ROLE.REP : ROLE.STUDENT

which means EVERY non-rep fell into "student" - advisers included. The
signup response and the profile both looked plausible, so nothing failed
loudly, but downstream every reader disagreed:

- needsAdviserVerification() requires role === "adviser", so the reopen
  banner never appeared for an adviser who dismissed the code modal
- ROLE_LABEL["student"] rendered "Regular Student" beside a Level
  Adviser's name
- verificationStatus was correctly "pending_email", so the code modal
  still opened, which made it look like a UI bug rather than a data one

The role is now decided in three cases, and only the rep branch is
conditional - an adviser application is always ROLE.ADVISER_PENDING,
because promotion to level_anchor belongs to api/verification.js once the
code is accepted, never to signup.
