feat(rep): refresh-safe sessions, visible-but-disabled GPS, semester report

Five fixes from the pre-test review.

1. REFRESH-SAFE REP SESSION. A rep who reloaded mid-class lost the
   countdown, because the timer lived in memory and startSessionTimer() was
   only ever called by the create path. The session listener now reads
   durationSeconds and pinRotationInterval from the SERVER rather than
   expecting them to be remembered, and restarts the timer when it finds
   none running. The PIN itself already came back via the secret listener,
   so the panel now returns exactly as it was left.

2. GPS MODES SHOWN, NOT HIDDEN. They were `return`ed out of the render
   loop, so a rep never learned they existed - which reads as a missing
   feature rather than a deliberate choice. Both now render greyed with a
   padlock, "Needs the mobile app", and a toast explaining that browser
   GPS is too imprecise indoors to tell one hall from the next. The
   fallback still routes to QR, so a stale saved preference cannot reach
   a disabled mode.

3. SPLASH. The entrance ran 1.1s but a tap in the first instant skipped
   all of it. Entrance stretched to 1.5s, the float now starts at 1.9s,
   and a tap inside the first 900ms is deferred rather than dropped, so
   the animation is actually seen.

4 + 5. SEMESTER REPORT AND EXPORTS. The document a Head of Department
   actually asks for: every class held and each student's percentage,
   with a per-session P/A column so "absent on the 3rd" is answerable
   separately from "60% overall". CSV for spreadsheets; "Save as PDF"
   opens the browser print dialog, which avoids a large dependency for a
   file nobody parses and gives selectable text that works on a phone.

   The maths lives in utils/report.js, not inline in an 8,000-line
   bundle, because a percentage that quietly counts a session twice still
   looks plausible in a table. Two decisions worth recording: percentages
   are whole numbers (66.7% implies precision a 20-student class cannot
   support), and flaggedAbsent is NOT subtracted - a flag is a staff
   decision and the rep may have flagged someone who was vouched for.

   Staff-only, and the exports refuse to run before any class has been
   held rather than producing an empty file.

utils/report.js is CommonJS so node can unit-test it, and also publishes
a global because the app imports Firebase from CDN URLs and so cannot
use a bare-specifier import for a local module. It is served no-cache so
a deploy cannot leave a stale report engine behind.
